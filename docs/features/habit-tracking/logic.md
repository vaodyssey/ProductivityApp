# Habit Tracking Logic

## Entities

### Capsule

- Location: `models\capsule.ts`
- Has a 1-M relationship with [Completion log](#completion_log)
- Includes these attributes:

```ts
interface Capsule {
  id: string; // should be generated by a utility function, in the format of CS_XXXXX (e.g. CS_00001)
  habitName: string; // The good habit name to build
  badAppName: string; // The name of the application to ditch
  goodImageUrl: string; // The image reminding the user of the good habit.
}
```

### Completion_log

- Location: `models\completion-log.ts`
- Has a M-1 relationship with [Capsule](#capsule)
- Includes these attributes:

```ts
interface CompletionLog {
  id: string; // should be generated by a utility function, in the format of CPL_XXXXX (e.g. CPL_00002)
  dateTime: string; // The UTC-style date time format (e.g. 2026-10-20T23:31:20Z)
  completed: boolean; // Indicates whether a habit (in the capsule form) is completed or not.
  capsuleId: string; // The reference to the originating Capsule (e.g. CS_00001)
}
```

## Business Logics

- All habit-tracking logics reside in `services\habit-tracking` folder.

### Mascot Mood

- Controls how happy/neutral/sad the mascot at the index screen appears.
- Greatly depends on the completion rate, which is calculated here [Completion Rate Calculation](#completion-rate-calculation)
  - Happy: Having the completion rate of over 0.8
  - Neutral: Having the completion rate of between 0.5 and 0.8
  - Sad: Having the completion rate of below 0.5

### Completion Rate calculation

Includes the following phases:

**_Phase 1: Retrieve weekly `completion_log` for each `capsule`_**

- Notes
  - Data retrival module for `completion_log` location: `repository\completion-log-repository.ts`
  - Data retrival module for `capsule` location: `repository\capsule-repository.ts` (TO BE UPDAETD IN CODE)

- Get the current DateTime, then deduct the week it belongs to.
  - Example: Today's October 21st, lying within October 19th - October 23rd (call this 1)
- For each `capsule` entry, retrieve its relevant `completion_log` entries with:
  - SQL JOIN statement.
  - Limit the `completion_log` entries whose `dateTime` lie within (1)

- The return result is a list of these items. This is located at `types` folder.

```ts
interface CapsuleCompletionResult {
  capsule: Capsule;
  completionLogs: CompletionLog[];
}
```

**_Phase 2: Calculate completion rate for all `CapsuleCompletionResult` items_**

- For each calculated `CapsuleCompletionResult` entry,
  - Count the number of `completionLogs` entries. This will be `timesPerWeek`
  - Set `completions = 0` For each `completionLogs` entry, if it contains `completed = true`, then add 1 to `completions`
  - Divide `completions` with `timesPerWeek`, round result up to 2 decimal points to retrieve `completionRate`.
  - Build a new object with the following attributes. This is located at `types` folder.

  ```ts
  interface CapsuleCompletionRate {
    capsule: Capsule;
    completionRate: number;
  }
  ```

- The logic should return a list of `CapsuleCompletionRate`.
- Trigger for Completion Rate calculation event will be on index screen > ProgressBuddy component: `components\per-screen\index\progress-buddy.tsx`
